## Design Specificity Verdict

**LLM assessment**: 界面是一套干净、克制、质量稳定的「GitHub Primer 浅色工具」——代码注释自己写着「明亮主题配色（GitHub light 系）」，蓝 #2f6fed、灰阶、8px 圆角、白卡片，任何开发工具都能原样使用。产品性格（化学、讲义、把格式钉死的执念）只在窗口图标「讲义」二字和文案里出现，视觉语言上不可见。对 Operate 模式这不是错误——克制优先于表达——但「品牌活在细节里」的机会全部让位给了泛用后台脸：状态色、进度条、空态都没有一处是化学讲义工具独有的。**判定：类别可互换（category-interchangeable），一致但无署名。**

**Deterministic scan**: not applicable (native platform)。Qt 桌面应用没有 web markup，`impeccable detect` 对其源码只会得到「干净」的假阴性，故按 native 路径跳过。

**Visual overlays**: 无浏览器可用，未注入 overlay；本会话无法目检截图。

## Overall Impression

工程上极其扎实：线程纪律、.part 语义、Key 打码、暂停/终止的诚实语义、配置原子写，都是小工具里罕见的水准——像一位优秀后端工程师写出来的工具 UI：信息密度高、反馈诚实，但把复杂度摊在用户面前，且对「手改定稿被静默覆盖」这类高代价错误没有护栏。最大机会：把决策收进渐进披露 + 堵住覆盖数据丢失，25 → 30+ 分并不难。

## What's Working

1. **长任务的运行控制堪称典范**：逐页进度 + 按页均速 ETA、文件级暂停/请求级终止的精确语义、.part 半成品可续传、日志里 API Key 自动打码——长时间运行的批量任务里用户最需要的确定性都给了。
2. **配置预览 + 快速失败**：「当前配置预览」让开跑前一眼看清要跑哪套引擎/网关/Key 状态；OpenAI 兼容引擎缺 Key/缺 URL 在启动前即报出明确提示，不会把智谱内置 Key 错发给别人网关。
3. **任务状态机与拖拽导入**：行级状态色 + 重转/移除、拖文件夹递归展开、自然序排序、占位符即默认值说明——主流程（拖进来 → 开始）几乎无学习成本。

## Priority Issues

### [P1] 已有讲义被静默覆盖（数据丢失风险）
- **What**: 「跳过已存在输出」默认关闭；教师手改定稿后的 `.md` 与源 PDF 同名，重跑即被整份覆盖，无任何确认。
- **Why it matters**: 教师的核心工作流是「转换 → 人工微调定稿」，手改内容被覆盖是真实的数据丢失，且发生时毫无提示。
- **Fix**: 启动前扫描任务目标，若存在完整输出且 skip_existing 未勾选 → 确认对话框列出将被覆盖的文件，提供「改为跳过已存在」一键切换；关闭窗口时同样拦截。
- **Suggested command**: /impeccable harden

### [P1] 动作时刻的「选项墙」
- **What**: 主按钮上方常驻 8 个决策（3 个路径字段 + 5 个复选框），与「开始转换」同屏竞争。
- **Why it matters**: 认知负荷清单在此失败 4 项（单一焦点、一次一件事、决策≤4）；教师每次开跑都要重扫一遍全部选项，多数时候只改 1 个。
- **Fix**: 折叠进「更多选项 ▾」渐进披露区（展开状态持久化），常驻只留「输出目录」「跳过已存在输出」；复选框默认值按教师实际频率重排。
- **Suggested command**: /impeccable distill

### [P1] 失败原因藏在 tooltip 里
- **What**: 任务行只显示状态词；PPT 转 PDF 失败的三条自救路径、异常原因全部收在悬浮提示中。
- **Why it matters**: 分享给同事时，Jordan 型用户永远看不到自救路径，只看到红色「失败」二字，直接卡死。
- **Fix**: 状态列下加第二行小字显示 message（失败时红色、成功时显示输出路径）；tooltip 保留全文。
- **Suggested command**: /impeccable clarify

### [P2] 暂停/终止状态不可见
- **What**: 暂停时进度条与标签纹丝不动，只有按钮文字变「继续」；终止等待期同样只在日志里说了一句。
- **Why it matters**: 长任务中用户离开再回来，无法一眼判断现在到底是「在跑」还是「停着」。
- **Fix**: 暂停 → 进度条 chunk 变琥珀 + 标签「已暂停（3/8 个文件）· 点『继续』恢复」；终止中 → 标签即时更新「正在终止，等待当前请求结束…」。
- **Suggested command**: /impeccable polish

### [P2] 效率缺口（Alex）
- **What**: 主操作无快捷键（Ctrl+Enter/F5）；任务列表不跨会话保存，每次启动重拖；不能勾选排除个别文件、不能调序。
- **Why it matters**: 核心用户就是重度用户：每周转多份课件，重复导入是最直接的每日摩擦。
- **Fix**: 开始转换 Ctrl+Enter、预演 Ctrl+P；任务清单（仅路径）持久化并在启动时恢复；加一列复选框控制是否纳入本批。
- **Suggested command**: /impeccable polish

## Persona Red Flags

**Alex（重度用户 · 教师本人）**: 点「开始转换」没有快捷键，必须鼠标穿越选项墙；任务列表不跨会话，每次启动重新拖文件夹；无法只转其中几份或调整顺序；五连复选框每次开跑都要重扫。→ 效率摩擦明确，但不至于弃用。

**Jordan（首次使用 · 同事）**: 导入 PPT 且本机没有 LibreOffice/pywin32 时，行内只显示「失败」，三条自救路径全在 tooltip 里，永远不会被发现；右侧「模型降级链 / max_tokens / OpenAI 兼容 / Base URL」黑话成片；没有任何首跑引导，除「拖进来点开始」外的一切（预演、体检、HTML 预览）都靠自行摸索。→ 在第一步就可能卡死。

**Sam（低视力 / 键盘用户）**: QSS 固定 13px 且 app 字体 9.5pt 被 QSS 覆盖，没有界面缩放入口；焦点样式只定义了输入框，按钮/表格行的默认 Fusion 焦点环很弱；日志 warn #9a6700 与表格 SKIPPED #6e7781 对比度处于边缘。→ 键盘主流程可行，但可读性与焦点反馈弱。

## Minor Observations

- PENDING(#57606a) 与 SKIPPED(#6e7781) 两种近灰难区分；PREPARING 与 CANCELLED 共用同一琥珀色——建议 SKIPPED 换色或加说明列。
- 输出 `.md` 路径只在 tooltip；成功后在「文件」列下加第二行小字显示输出路径更实用。
- 「预演」按钮与「开始转换」分处两地，dry-run 这个省钱入口不够显眼。
- 状态栏文案与文件面板底部 hint 内容重复。
- 模型面板标题行挤了 6 个控件（标题+combo+4 按钮），小窗下必然挤压。
- 空态（无任务时）只有计数标签与一行灰字，缺一个明确的第一步引导。
- 「关于」对话框有内容但无版本号。

## Questions to Consider

- 如果「开始转换」永远只需要两个决策（哪套配置、输出到哪），其余全部折叠，教师会不会更快进入工作？
- 讲义是给学生看的最终产物——工具界面是否也值得带一点「化学笔记」的气质，而不是一副 GitHub 后台脸？
- 同事拿到这个工具，能不能在 30 秒内、不读任何文档地跑通第一份讲义？
